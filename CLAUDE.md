# CLAUDE.md - Pulse Project Guidelines

## Project Overview

**Pulse** is a Distributed Task Orchestrator built with Python/FastAPI. It provides a robust platform for scheduling, executing, and monitoring distributed tasks across multiple workers.

## Tech Stack

- **Framework**: Python 3.11+ with FastAPI
- **Database**: PostgreSQL with SQLAlchemy ORM
- **Authentication**: JWT (JSON Web Tokens)
- **Task Queue**: Celery with Redis as broker
- **Testing**: pytest with pytest-asyncio
- **API Documentation**: OpenAPI/Swagger (auto-generated by FastAPI)

## Core Requirements

### 1. JWT Authentication
- Secure user registration and login
- Access tokens with configurable expiration
- Refresh token rotation
- Password hashing with bcrypt
- Protected endpoints via dependency injection

### 2. REST API Design
- RESTful resource naming conventions
- Proper HTTP status codes
- Consistent error response format
- API versioning (v1)
- Request/response validation with Pydantic

### 3. High Test Coverage Target
- **Target: 80%+ code coverage**
- Unit tests for all services
- Integration tests for API endpoints
- Fixtures for database and authentication
- Mocking external dependencies

## API Endpoints

### Authentication
- `POST /api/v1/auth/register` - User registration
- `POST /api/v1/auth/login` - User login (returns JWT)
- `POST /api/v1/auth/refresh` - Refresh access token
- `GET /api/v1/auth/me` - Get current user

### Tasks
- `GET /api/v1/tasks` - List tasks (with pagination/filtering)
- `POST /api/v1/tasks` - Create new task
- `GET /api/v1/tasks/{id}` - Get task details
- `PUT /api/v1/tasks/{id}` - Update task
- `DELETE /api/v1/tasks/{id}` - Delete task
- `POST /api/v1/tasks/{id}/execute` - Execute task
- `GET /api/v1/tasks/{id}/status` - Get task execution status

### Workers
- `GET /api/v1/workers` - List registered workers
- `POST /api/v1/workers/register` - Register new worker
- `GET /api/v1/workers/{id}` - Get worker details
- `DELETE /api/v1/workers/{id}` - Deregister worker
- `GET /api/v1/workers/{id}/health` - Worker health check

## Development Guidelines

### Code Style
- Follow PEP 8 style guide
- Use type hints throughout
- Docstrings for public functions/classes
- Maximum line length: 88 characters (Black formatter)

### Git Workflow
- Feature branches from `main`
- Descriptive commit messages
- PR required for merging to main

### Testing Commands
```bash
# Run all tests
pytest

# Run with coverage
pytest --cov=app --cov-report=html

# Run specific test file
pytest tests/test_auth.py -v
```

### Running the Application
```bash
# Install dependencies
pip install -r requirements.txt

# Run development server
uvicorn app.main:app --reload

# Run with Docker
docker-compose up
```
